Documentazione Tecnica

Architettura del backend, struttura dei dati e le tre soluzioni di Machine Learning a confronto.

Architettura tecnica del sistema

GustAvo adotta un'architettura client-server modulare a componenti disaccoppiati, progettata per essere eseguita in modo efficiente sull'infrastruttura scolastica:

  • Frontend Web (HTML5 / CSS3 / JavaScript): interfaccia conversazionale reattiva e accessibile, ottimizzata per desktop e dispositivi mobili.
  • Backend API (Python / Flask): server web leggero che espone l'endpoint /chat per ricevere ed elaborare le richieste POST in formato JSON, con abilitazione CORS per la sicurezza delle chiamate cross-origin.
  • Motore di Classificazione NLP (Scikit-Learn): pipeline di pre-elaborazione del testo che trasforma le frasi in vettori numerici (TF-IDF) e determina la similarità con gli intenti censiti.
  • Knowledge Base (intents.json): archivio strutturato contenente le categorie, i pattern di addestramento e le risposte ufficiali certificate dalla scuola.

Ciclo di vita della richiesta (Workflow)

Il flusso operativo che trasforma una domanda dell'utente in una risposta certa segue cinque passaggi sequenziali:

  1. Input dell'utente: lo studente digita la propria domanda nel campo di testo dell'interfaccia.
  2. Inoltro HTTP: il client web effettua una chiamata asincrona (fetch POST) inviando il payload { "message": "..." } all'endpoint /chat.
  3. Vettorizzazione e Classificazione: il server pre-elabora il messaggio, lo converte in vettore numerico tramite TfidfVectorizer e calcola la similarità coseno con ciascun pattern di addestramento.
  4. Identificazione dell'intento: l'algoritmo seleziona il tag con il punteggio di confidenza più alto. Se il punteggio supera la soglia prefissata (threshold), l'intento viene validato; in caso contrario, scatta il fallback di sicurezza ("Non ho capito bene la domanda").
  5. Erogazione della risposta: il server estrae la risposta convalidata associata al tag individuato e la restituisce al client in formato JSON per la visualizzazione a schermo.

Struttura del software e tecnologie utilizzate

I componenti software del repository del bot corrispondono alla struttura ufficiale documentata:

  • app.py: entrypoint del server Flask, gestione del routing API /chat e logica di predizione.
  • intents.json: file sorgente della conoscenza, contenente tag, pattern di domanda e risposte.
  • index.html: interfaccia web interattiva con logica di messaggistica asincrona (JavaScript).
  • requirements.txt: elenco delle dipendenze Python necessarie per l'esecuzione dell'ambiente.

Oltre al classificatore standard in Scikit-Learn, nei laboratori è stato sperimentato anche l'uso di Sentence-Transformers (modello all-MiniLM-L6-v2) per confrontare l'accuratezza semantica degli embedding densi con l'approccio vettoriale classico.

Il sistema degli intenti e il file intents.json

GustAvo non adotta un approccio generativo libero (come i grandi modelli LLM), ma opera come un classificatore supervisionato basato su intenti. Questa scelta architetturale garantisce:

  • Risposte convalidate e certe: il bot attinge unicamente a risposte verificate dall'istituto, eliminando il rischio di allucinazioni o informazioni inventate.
  • Efficienza e sostenibilità: consumo ridotto di CPU e RAM, consentendo l'hosting autonomo sui server della scuola senza costi di computazione esterni.
  • Tutela dei dati: assenza di conservazione di cronologia, cookie di tracciamento o profilazione degli utenti.

Esempio reale di struttura da intents.json: 

{
  "tag": "indirizzi_studio",
  "patterns": [
    "Quali corsi offre l'Avogadro?",
    "Quali indirizzi ci sono?",
    "Cosa si studia all'Avogadro?"
  ],
  "responses": [
    "L'istituto offre corsi tecnici in Informatica, Elettronica, Meccanica e il Liceo Scientifico delle Scienze Applicate."
  ]
}

Spiegazione dei campi:

  • tag: categoria semantica della richiesta.
  • patterns: insieme di esempi e formulazioni alternative con cui la domanda può essere posta dall'utente.
  • responses: risposta o elenco di risposte certificate che il sistema restituisce quando il tag viene classificato.

I tre modelli a confronto

Durante le sessioni di laboratorio didattico sono state sviluppate e sperimentate tre soluzioni architetturali distinte:

1. TF-IDF + Similarità Coseno

Architettura attiva (gustavo1): trasforma le frasi in vettori pesati con TF-IDF e calcola l'angolo di similarità rispetto ai pattern. È estremamente leggero su CPU/RAM e offre risposte istantanee su insiemi controllati di FAQ.

2. TF-IDF + Rete Neurale (MLP)

Soluzione supervisionata (gustavo2): rete neurale Multi-Layer Perceptron (strato nascosto a 10 neuroni con attivazione ReLU e Softmax). Offre maggiore stabilità con frasi rumorose o variazioni sintattiche.

3. Sentence Transformer (Embedding)

Soluzione semantica (gustavo3): impiega il modello pre-addestrato all-MiniLM-L6-v2 per generare vettori densi a 384 dimensioni. Coglie il significato intrinseco riconoscendo sinonimi e parafrasi complesse.
